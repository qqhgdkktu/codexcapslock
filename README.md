# Codex Caps Lock Indicator

[![CI](https://github.com/qqhgdkktu/codexcapslock/actions/workflows/ci.yml/badge.svg)](https://github.com/qqhgdkktu/codexcapslock/actions/workflows/ci.yml)

Нативный индикатор активности Codex для MacBook. Он использует зелёный LED в клавише Caps Lock, но отправляет напрямую только HID output-report светодиода — настоящий режим Caps Lock и регистр набора не переключаются.

## Быстрый старт

Понадобятся:

- MacBook со встроенной клавиатурой и физическим LED Caps Lock;
- macOS 14 или новее;
- установленный Codex, команда `codex` в `PATH`;
- Swift toolchain из Xcode или Xcode Command Line Tools.

```bash
git clone https://github.com/qqhgdkktu/codexcapslock.git
cd codexcapslock
python3 scripts/install.py
```

После установки просто запустите задачу в Codex. Дополнительное приложение открывать не нужно: первый lifecycle hook запустит индикатор автоматически, в том числе после перезагрузки Mac.

Проверить установку:

```bash
~/.local/bin/codex-capslock-indicator status
```

Полное руководство со сценариями, обновлением и диагностикой: [docs/USAGE.md](docs/USAGE.md). Инструкции для Codex и других AI-агентов: [AGENTS.md](AGENTS.md).

## Поведение

| Состояние Codex | LED Caps Lock |
| --- | --- |
| Выполняет задачу | Мигает: 0,5 с включён / 0,5 с выключен |
| Ждёт подтверждения или ответа | Горит постоянно |
| Завершил задачу, результат ещё не просмотрен | Горит постоянно |
| Результат просмотрен | Гаснет и возвращается к обычной индикации Caps Lock |
| Приложение Codex закрыто | Возвращается к обычному состоянию Caps Lock; фоновый процесс завершается |

Если одновременно открыто несколько задач, работа хотя бы одной задачи имеет приоритет и LED мигает.

## Как погасить завершение

Постоянный свет после завершения — это уведомление о непросмотренном результате. Его можно подтвердить тремя способами:

- нажать Caps Lock: первое нажатие гасит уведомление и гарантированно оставляет обычный Caps Lock выключенным; следующее нажатие снова работает стандартно;
- открыть Codex и оставить его на переднем плане на секунду — результат считается просмотренным автоматически;
- выполнить `~/.local/bin/codex-capslock-indicator ack`.

Если Codex уже открыт на переднем плане, завершение остаётся видимым минимум две секунды и затем гаснет. Ожидание подтверждения или ответа не скрывается этим механизмом: после нужного действия Codex сам вернётся в рабочее состояние.

Индикатор не устанавливает перехватчик клавиатуры, не читает набранный текст и не требует Accessibility или Input Monitoring. Он сверяет только системный флаг Caps Lock, когда горит завершение.

## Повторная установка или обновление

```bash
git pull --ff-only
python3 scripts/install.py
```

Установщик:

- запускает Swift-тесты и собирает release-бинарник;
- аппаратно проверяет, что LED меняется отдельно от режима Caps Lock;
- добавляет пять lifecycle hooks в `~/.codex/hooks.json`, сохраняя чужие hooks и текущий `notify`;
- доверяет только добавленным hooks через локальный Codex app-server;
- запускает индикатор из доверенного пользовательского контекста Codex; после перезапуска Mac он автоматически стартует с первой задачей Codex;
- сохраняет резервную копию затронутой конфигурации в `~/.codex/backups/codex-capslock-indicator/`.

## Проверка и демонстрация

```bash
~/.local/bin/codex-capslock-indicator status
~/.local/bin/codex-capslock-indicator ack
~/.local/bin/codex-capslock-indicator self-test
~/.local/bin/codex-capslock-indicator demo
```

`demo` показывает четыре секунды мигания и две секунды постоянного света, после чего восстанавливает обычную индикацию Caps Lock.

## Удаление

```bash
python3 scripts/uninstall.py
```

Скрипт удаляет только свои hooks, бинарник и оставшийся от старой установки LaunchAgent. Логи и резервные копии остаются для диагностики.

## Как это устроено

- Hooks `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse` и `Stop` дают основные сигналы жизненного цикла.
- Локальный transcript служит резервным источником для начала/конца задачи и `request_user_input`.
- Локальный журнал app-server помогает определить возврат из системного окна подтверждения.
- В журнал индикатора не копируются тексты запросов, команды или ответы Codex — только идентификаторы сессии/хода и состояние.
- Проверки объединены в один таймер с шагом 250 мс; transcript читается не чаще двух раз в секунду, журнал app-server — раз в секунду, процесс Codex — раз в пять секунд.
- Hook проверяет singleton-lock и не создаёт новый процесс, когда daemon уже работает.
- Наличие desktop-приложения определяется через системный AppKit API без запуска `pgrep`; CLI-проверка используется только как резервный путь.
- Поиск transcript ограничен сегодняшним и вчерашним каталогами сессий, без обхода всей истории Codex.
- Файл статуса записывается при изменении состояния и не чаще одного раза в 30 секунд, поэтому мигание не создаёт постоянных дисковых записей.
- У приложения нет окон, рендеринга и GPU-нагрузки.

Проект рассчитан на встроенную клавиатуру MacBook с физическим Caps Lock LED. Цвет аппаратно фиксирован зелёным и программно не меняется.

# Codex MagSafe / Caps Lock Indicator

[![CI](https://github.com/qqhgdkktu/codexcapslock/actions/workflows/ci.yml/badge.svg)](https://github.com/qqhgdkktu/codexcapslock/actions/workflows/ci.yml)

Нативный аппаратный индикатор активности Codex для MacBook:

- если подключён MagSafe 3, работает только LED на коннекторе MagSafe;
- если MagSafe отключён, работает только зелёный LED Caps Lock;
- переключение происходит автоматически примерно за секунду.

Caps Lock остаётся обычной клавишей, когда выбран MagSafe. В резервном режиме программа отправляет напрямую только HID output-report светодиода Caps Lock — настоящий режим Caps Lock и регистр набора не переключаются.

## Быстрый старт

Понадобятся:

- MacBook со встроенной клавиатурой и физическим LED Caps Lock;
- macOS 14 или новее;
- установленный Codex, команда `codex` в `PATH`;
- Swift toolchain из Xcode или Xcode Command Line Tools.

```bash
git clone https://github.com/qqhgdkktu/codexcapslock.git
cd codexcapslock
python3 scripts/install.py
```

На MacBook с MagSafe 3 установщик один раз покажет защищённое системное окно администратора. Оно нужно только маленькому локальному помощнику, потому что запись в системный SMC разрешена macOS только привилегированному процессу. На Mac без MagSafe окно не появляется.

После установки просто запустите задачу в Codex. Дополнительное приложение открывать не нужно: первый lifecycle hook запустит индикатор автоматически, в том числе после перезагрузки Mac.

Проверить установку:

```bash
~/.local/bin/codex-capslock-indicator status
```

Полное руководство со сценариями, обновлением и диагностикой: [docs/USAGE.md](docs/USAGE.md). Инструкции для Codex и других AI-агентов: [AGENTS.md](AGENTS.md).

## Как выбирается индикатор

| Подключение | Активный индикатор | Второй индикатор |
| --- | --- | --- |
| MagSafe 3 подключён | MagSafe | Caps Lock полностью возвращён macOS и работает обычно |
| MagSafe 3 отключён | Caps Lock | MagSafe возвращён в обычный системный режим зарядки |
| MagSafe найден, но системный помощник недоступен | Caps Lock как безопасный резерв | Ошибка видна в `status` |

Зарядка через USB-C не считается MagSafe: программа проверяет отдельный физический порт MagSafe 3, а не просто наличие внешнего питания.

## Поведение Codex

| Состояние Codex | Выбранный LED |
| --- | --- |
| Выполняет задачу | Мигает; MagSafe использует энергоэффективный встроенный режим, Caps Lock — 0,5 с включён / 0,5 с выключен |
| Ждёт подтверждения или ответа | Горит постоянно зелёным |
| Завершил задачу, результат ещё не просмотрен | Горит постоянно зелёным |
| Результат просмотрен | MagSafe возвращается к системному цвету зарядки, Caps Lock — к своему реальному состоянию |
| Приложение Codex закрыто | Оба LED возвращаются под управление macOS; пользовательский фоновый процесс завершается |

Если одновременно открыто несколько задач, работа хотя бы одной задачи имеет приоритет и LED мигает.

## Как погасить завершение

Постоянный свет после завершения — это уведомление о непросмотренном результате. Его можно подтвердить тремя способами:

- когда активен Caps Lock — нажать Caps Lock: первое нажатие гасит уведомление и гарантированно оставляет обычный Caps Lock выключенным;
- открыть Codex и оставить его на переднем плане на секунду — результат считается просмотренным автоматически;
- выполнить `~/.local/bin/codex-capslock-indicator ack`.

Когда подключён MagSafe, Caps Lock не используется даже как кнопка подтверждения: он включает и выключает обычный режим заглавных букв. Завершение на MagSafe сбрасывается открытием Codex или командой `ack`.

Если Codex уже открыт на переднем плане, завершение остаётся видимым минимум две секунды и затем гаснет. Ожидание подтверждения или ответа не скрывается этим механизмом: после нужного действия Codex сам вернётся в рабочее состояние.

Индикатор не устанавливает перехватчик клавиатуры, не читает набранный текст и не требует Accessibility или Input Monitoring. Он сверяет только системный флаг Caps Lock, когда горит завершение.

## Повторная установка или обновление

```bash
git pull --ff-only
python3 scripts/install.py
```

Установщик:

- запускает Swift-тесты и собирает release-бинарник;
- на Mac с MagSafe устанавливает компактный root-помощник и проверяет SMC-канал `ACLC`;
- аппаратно проверяет оба доступных LED и неизменность режима Caps Lock;
- добавляет пять lifecycle hooks в `~/.codex/hooks.json`, сохраняя чужие hooks и текущий `notify`;
- доверяет только добавленным hooks через локальный Codex app-server;
- запускает индикатор из доверенного пользовательского контекста Codex; после перезапуска Mac он автоматически стартует с первой задачей Codex;
- сохраняет резервную копию затронутой конфигурации в `~/.codex/backups/codex-capslock-indicator/`.

## Проверка и демонстрация

```bash
~/.local/bin/codex-capslock-indicator status
~/.local/bin/codex-capslock-indicator ack
~/.local/bin/codex-capslock-indicator self-test
~/.local/bin/codex-capslock-indicator demo
~/.local/bin/codex-capslock-indicator inspect-magsafe
```

`demo` сам выбирает MagSafe или Caps Lock, показывает четыре секунды мигания и две секунды постоянного света, затем восстанавливает обычную системную индикацию.

## Удаление

```bash
python3 scripts/uninstall.py
```

Скрипт удаляет только свои hooks, пользовательский бинарник, системный помощник MagSafe и оставшийся от старой установки LaunchAgent. Если помощник установлен, macOS снова покажет защищённое окно администратора. Логи и резервные копии остаются для диагностики.

## Как это устроено

- Hooks `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse` и `Stop` дают основные сигналы жизненного цикла.
- Локальный transcript служит резервным источником для начала/конца задачи и `request_user_input`.
- Локальный журнал app-server помогает определить возврат из системного окна подтверждения.
- В журнал индикатора не копируются тексты запросов, команды или ответы Codex — только идентификаторы сессии/хода и состояние.
- Проверки объединены в один таймер с шагом 250 мс; transcript читается не чаще двух раз в секунду, журнал app-server — раз в секунду, процесс Codex — раз в пять секунд.
- Физический порт MagSafe проверяется локально через IOKit раз в секунду; запись в SMC выполняется только при смене состояния, а миганием занимается прошивка MagSafe.
- Системный помощник написан на C, блокируется в ожидании локальной команды и не выполняет опросов, сетевых запросов или графической работы.
- Hook проверяет singleton-lock и не создаёт новый процесс, когда daemon уже работает.
- Наличие desktop-приложения определяется через системный AppKit API без запуска `pgrep`; CLI-проверка используется только как резервный путь.
- Поиск transcript ограничен сегодняшним и вчерашним каталогами сессий, без обхода всей истории Codex.
- Файл статуса записывается при изменении состояния и не чаще одного раза в 30 секунд, поэтому мигание не создаёт постоянных дисковых записей.
- У приложения нет окон, рендеринга и GPU-нагрузки.

Управление MagSafe основано на недокументированном SMC-ключе `ACLC`, поэтому крупное обновление macOS или прошивки теоретически может его изменить. При недоступном канале программа автоматически использует Caps Lock. За основу SMC-части взят MIT-проект [MagSafe Dark](https://github.com/bulava92/magsafe-dark); полный текст лицензии находится в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

# Использование Codex MagSafe / Caps Lock Indicator

Это руководство рассчитано на обычного пользователя. Для инструкций по изменению и автоматической проверке проекта см. [AGENTS.md](../AGENTS.md).

## Что делает индикатор

Программа автоматически использует один из двух аппаратных LED:

1. Подключён физический MagSafe 3 — работает только MagSafe.
2. MagSafe отключён — работает только Caps Lock.

Зарядка по USB-C не переключает индикатор на MagSafe. Состояния выглядят так:

| Ситуация | Что делает LED | Что делать пользователю |
| --- | --- | --- |
| Codex выполняет задачу | Мигает | Можно работать в другом приложении |
| Codex ждёт разрешения или ответа | Горит постоянно | Открыть Codex и выполнить требуемое действие |
| Codex закончил, результат не просмотрен | Горит постоянно | Открыть Codex, выполнить `ack` или нажать Caps Lock, если он выбран как индикатор |
| Результат просмотрен | Возвращается к обычной системной индикации | Ничего |
| Codex закрыт | Оба LED возвращаются macOS, пользовательский daemon завершается | Ничего |

В режиме Caps Lock индикатор не включает настоящий режим заглавных букв. Когда выбран MagSafe, клавиша и LED Caps Lock полностью работают как обычно.

## Установка

### 1. Проверить требования

- MacBook со встроенным физическим LED Caps Lock.
- macOS 14 или новее.
- Установленный Codex Desktop или Codex CLI.
- Команды `codex`, `swift` и `python3` доступны в терминале.

MagSafe-индикация дополнительно требует MacBook на Apple Silicon с портом MagSafe 3. На остальных моделях программа продолжает работать через Caps Lock.

Проверка:

```bash
codex --version
swift --version
python3 --version
```

Если `swift` отсутствует, установите Xcode Command Line Tools:

```bash
xcode-select --install
```

### 2. Скачать и установить

```bash
git clone https://github.com/qqhgdkktu/codexcapslock.git
cd codexcapslock
python3 scripts/install.py
```

Установщик сам:

1. запускает тесты и собирает release-бинарник;
2. устанавливает бинарник в `~/.local/bin/codex-capslock-indicator`;
3. при наличии MagSafe ставит root-помощник и проверяет совпадение его хеша с release-сборкой;
4. проверяет доступные физические LED без изменения режима ввода;
5. добавляет свои lifecycle hooks, сохраняя существующие hooks и `notify`;
6. доверяет добавленным hooks через локальный Codex app-server;
7. сохраняет резервную копию изменяемой конфигурации в `~/.codex/backups/codex-capslock-indicator/`.

На MacBook с портом MagSafe установщик один раз покажет защищённое системное окно администратора. Это ожидаемо: SMC разрешает менять режим LED только привилегированному локальному помощнику. Помощник принимает лишь фиксированные команды LED от активного пользователя, не имеет доступа к задачам Codex и не использует сеть. На Mac без MagSafe окно не появляется.

### 3. Начать пользоваться

Откройте Codex и отправьте любую задачу. При начале работы LED должен мигать. После перезагрузки Mac отдельный автозапуск настраивать не нужно: daemon снова появится с первым событием Codex.

## Как погасить завершённую задачу

Когда Codex закончил работу, постоянный свет означает непросмотренный результат. Есть три способа его погасить:

1. Открыть Codex и оставить его на переднем плане примерно на секунду.
2. Если активен индикатор Caps Lock — нажать Caps Lock. Первое нажатие погасит уведомление и оставит настоящий Caps Lock выключенным.
3. Выполнить:

```bash
~/.local/bin/codex-capslock-indicator ack
```

Состояние ожидания разрешения или ответа так не скрывается. LED погаснет или снова начнёт мигать после фактического действия в Codex.

Если подключён MagSafe, нажатие Caps Lock не подтверждает результат и просто управляет обычным Caps Lock. Используйте открытие Codex или `ack`.

## Основные команды

| Команда | Назначение | Безопасность |
| --- | --- | --- |
| `~/.local/bin/codex-capslock-indicator --version` | Показать установленную версию | Только чтение |
| `~/.local/bin/codex-capslock-indicator status` | Показать состояние daemon, Codex и клавиатуры | Только чтение |
| `~/.local/bin/codex-capslock-indicator ack` | Отметить завершённые задачи просмотренными | Не скрывает ожидание действия |
| `~/.local/bin/codex-capslock-indicator self-test` | Кратко переключить LED и проверить неизменность реального Caps Lock | Автоматически восстанавливает LED |
| `~/.local/bin/codex-capslock-indicator demo` | Показать автоматически выбранный индикатор | Длится около шести секунд и восстанавливает оба LED |
| `~/.local/bin/codex-capslock-indicator inspect-led` | Показать физический LED и реальный режим Caps Lock отдельно | Только чтение |
| `~/.local/bin/codex-capslock-indicator inspect-magsafe` | Показать порт, подключение и доступность управления MagSafe | Только чтение |
| `python3 scripts/install.py` | Собрать, проверить и установить текущую версию | Делает резервную копию конфигурации |
| `python3 scripts/uninstall.py` | Удалить бинарник и только hooks этого проекта | Диагностические данные и резервные копии сохраняются |

Команды `hook`, `led`, `raw-led` и `magsafe` являются внутренними или диагностическими. Для обычного использования они не нужны.

## Обновление

В каталоге репозитория:

```bash
git pull --ff-only
python3 scripts/install.py
```

Повторный установщик безопасно заменяет свою предыдущую версию и заново проверяет LED и hooks.

## Диагностика

### LED не реагирует

```bash
~/.local/bin/codex-capslock-indicator status
~/.local/bin/codex-capslock-indicator self-test
```

Проверьте, что используется встроенная клавиатура MacBook с физическим LED. Внешние клавиатуры могут предоставлять другой HID-интерфейс и официально не поддерживаются.

### Подключён MagSafe, но мигает Caps Lock

```bash
~/.local/bin/codex-capslock-indicator inspect-magsafe
~/.local/bin/codex-capslock-indicator status
```

Нормальный результат при подключённом кабеле: `Физическое подключение: да`, `Управление LED: доступно`, `Индикатор: MagSafe`. Если управление недоступно, повторите `python3 scripts/install.py`: установщик заново проверит системный помощник и его хеш.

### Зарядка подключена по USB-C

Это не MagSafe. В таком случае программа намеренно оставляет активным Caps Lock, даже если Mac получает внешнее питание.

### `status` сообщает, что индикатор ещё не запущен

Отправьте любую задачу в Codex. Первый hook должен запустить daemon. Затем повторите `status`.

### LED горит, но печать идёт обычными буквами

Это ожидаемо: LED показывает Codex, а настоящий Caps Lock остаётся выключенным. Сравнить два состояния можно командой:

```bash
~/.local/bin/codex-capslock-indicator inspect-led
```

### После обновления что-то работает неправильно

Повторите установку из актуального каталога репозитория:

```bash
git pull --ff-only
python3 scripts/install.py
```

Установщик выведет путь к свежей резервной копии конфигурации. Не удаляйте и не заменяйте вручную весь `~/.codex/hooks.json`: там могут находиться hooks других инструментов.

## Удаление

Из каталога репозитория:

```bash
python3 scripts/uninstall.py
```

Удаляются только пользовательский бинарник, системный помощник MagSafe и hooks этого проекта. Чужие hooks, текущий `notify`, диагностические файлы и резервные копии сохраняются.

## Приватность и энергопотребление

- Не читаются тексты запросов, ответы, команды или нажатия клавиш.
- Не устанавливаются Accessibility и Input Monitoring permissions.
- В локальный журнал записываются только идентификаторы сессии/хода, тип события, состояние и время.
- Нет окон, меню, графического рендеринга, сетевых запросов или отдельного GPU-процесса.
- Hooks не создают дубликат daemon, если он уже работает.
- Системный помощник MagSafe написан на C и спит в ожидании локальной команды; он не опрашивает Codex или оборудование.
- Физическое мигание MagSafe выполняет прошивка, поэтому программа пишет в SMC только при смене состояния.

## Техническое ограничение MagSafe

Apple не документирует SMC-ключ управления LED MagSafe. Реализация использует проверенный ключ `ACLC` из проекта [MagSafe Dark](https://github.com/bulava92/magsafe-dark). После крупного обновления macOS или прошивки запустите `self-test`. Если SMC-канал недоступен, программа безопасно возвращается к Caps Lock.
